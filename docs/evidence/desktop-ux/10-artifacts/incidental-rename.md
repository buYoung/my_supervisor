# 범위 밖 이름 변경 관찰

INPUT-05의 초기 실행에서 의도하지 않은 `native-input` → `native-inputㄱ` 변경이 함께 제출됐다. 이 입력이 만들어진 경로는 확정하지 않았다. 저장소의 기존 이름 변경 경로는 `FOREIGN KEY constraint failed`를 반환했고, UI는 이를 성공으로 숨기지 않았다. [축약된 원본 증거](incidental-rename.json)를 보존한다.

이 시나리오는 이름 변경 없이 비활성 정책 초안과 저장값을 확인하는 검사다. 이후 저장 전 대상 이름을 확인하도록 보완했다. 프로세스 이름 변경 시 참조 키를 이전하는 저장소 로직은 이 UX 브리프에서 바꾸지 않았으며, 해당 관찰을 해결했다고 주장하지 않는다.
