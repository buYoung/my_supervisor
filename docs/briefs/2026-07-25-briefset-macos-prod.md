# Brief Set: Production-grade macOS process and schedule supervision

## Purpose
- Deliver a macOS production supervisor for arbitrary executables with PM2-level lifecycle operations and deterministic cron-plus scheduling.
- Preserve current process-group safety, durable recovery, local-only control, and configuration/API compatibility while adding the missing production behavior.

## Shared Constraints
- macOS user scope and loopback-only control are hard boundaries; Linux, Windows, root services, and remote multi-node orchestration are excluded.
- Target arbitrary executables with generic PM2-equivalent supervision; do not clone Node.js-specific cluster internals.
- New jobs default to an explicit macOS IANA timezone; existing cron definitions retain UTC. Nonexistent DST local times skip; repeated local times select the earlier UTC instant exactly once; missed work defaults to `run_once`, and bounded catch-up is optional.
- Legacy jobs migrate with missed-run `skip` to preserve the current no-catch-up behavior; `run_once` is the default only for newly created jobs. Existing `Parallel` remains equivalent below the production caps, but exceeding the new bounds is an explicit safety compatibility exception and returns a persisted overflow outcome.
- Direct-process memory ceilings measure aggregate resident memory for the owned process group, including descendants; PID-only measurement cannot satisfy the production limit.
- The installed loopback control plane requires a per-install 256-bit bearer credential stored in a user-only (`0600`) file, authenticated before any operation, never exposed to browser JavaScript or logs, and rotated explicitly; user-scoped launchd and loopback binding alone are not authentication.
- Each child records semantic/manual evidence in its proposed `docs/evidence/macos-prod-<wave>-*.md`; every record includes revision, exact command or fixture preparation, isolated data/label, precondition, action, expected and observed result, status, cleanup, and owning follow-up. Wave 10 indexes these records in `docs/PRODUCTION_READINESS.md`.
- Semantic macOS scenarios use a `mktemp -d` root, an unused loopback port, `MSV_DAEMON_TEST_DATA_DIR`, `MSV_DAEMON_TEST_CONFIG_PATH`, `MSV_DAEMON_TEST_BIND_ADDR`, and the private `MSV_DAEMON_TEST_CONTROL_SOCKET` with `cargo run -p my-supervisor-app-daemon --bin msv-daemon`; drive public actions through `cargo run -p my-supervisor-app-cli --bin msv -- --url http://127.0.0.1:<port> ...`, record SQLite/API/process identities, terminate the process group, and remove only that validated temporary root. If a required failure boundary lacks a private debug control, add the narrow control to the existing debug-only daemon host rather than creating a new test file.
- Legacy migration evidence is created from a detached temporary worktree at baseline `a1c845c`: build the old daemon/CLI, create representative state through public commands under the isolated debug environment, stop it cleanly, copy the database/config/log root, remove the worktree, and open the copy exactly once with the candidate binary before inspecting rows and foreign keys.
- Preserve old config keys, serialized enum values, SQLite rows, API routes/error codes, CLI behavior, Tauri command/event names, log cursors, and stable IDs through additive contracts or explicit migrations.
- Preserve caller cancellation, generation checks, process-group shutdown, deletion/config sagas, terminal outbox delivery, and dependency-signature idempotency.
- Required pre-implementation closure — process contract (`...-01-process-contract.md`): close the exact logical group/instance/execution-ID schema, validation-before-mutation route (including conversion), optional-policy null semantics, migration crash seam, and remaining numeric policy defaults/limits.
- Required pre-implementation closure — runtime guards (`...-02-runtime-guards.md`): select the macOS process-group RSS aggregation route, external-check executor boundary, file-watch backend/overflow state machine, durable guardrail evidence model, worker lifecycle, and reproducible cancellation/restart scenarios.
- Required pre-implementation closure — schedule contract (`...-04-schedule-contract.md`): close the macOS IANA resolver/error boundary, revision compare-and-swap repository/API contract, scheduler-to-`JobRunner` original-time context, canonical preview routes/commands, TypeScript client propagation, and executable migration/preview fixtures.
- Required pre-implementation closure — telemetry and alerts (`...-07-telemetry-alerts.md`): close the atomic authoritative-transition/outbox API, worker ownership/drain order, Notification Center execution identity and entitlement path, retention-safe pagination, deleted-source tombstones, race-safe hook execution, and bounded cleanup/admission policy.
- Required pre-implementation closure — operator surfaces (`...-08-operator-ui.md`): freeze the complete capability/parity matrix, native session-bootstrap/cookie/CSRF contract, CLI JSON-v2/exit matrix, and debug-only partition-failure/scale fixture. Installed-owner authentication/discovery from Wave 8 is an explicit prerequisite.
- Required pre-implementation closure — service ownership (`...-09-service-owner.md`): close the supervisor LaunchAgent `KeepAlive` versus intentional-stop state machine, legacy managed-process plist path rewrite/rollback, and per-management-mode child survival/reconciliation policy during upgrade handoff.
- These closures are blocking design work, not optional enhancements. Resolved decisions and observed evidence must be written into the owning child evidence file before that child is complete; any unresolved item blocks the Wave 10 production-ready decision.
- Do not add new test files/cases or lint/format setup without separate user approval; use existing suites and bounded real macOS scenarios.
- Do not publish, sign, notarize, deploy, delete user data, or modify external systems without separate explicit approval and credentials.

## Global Acceptance Criteria
- [ ] A macOS login or daemon crash restores exactly one supervisor owner, configured process groups, durable schedule state, queued/retry work, and diagnostics without duplicate children or logical occurrences.
- [ ] Direct processes support bounded restart policy, file watch, memory ceiling, liveness/readiness, multi-instance scale, per-instance status, and readiness-gated rolling replacement.
- [ ] Cron scheduling supports explicit IANA timezone, deterministic DST behavior, preserved original scheduled time, `skip`/`run_once`/bounded `catch_up`, retry/backoff, queue/concurrency limits, dependency final outcomes, cancellation, and durable history.
- [ ] Process/run logs rotate and retain bounded storage while numeric cursor tail/follow remains gap-free for retained entries across rollover and restart.
- [ ] Metrics, events, and alerts are bounded, durable where required, deduplicated, acknowledgeable, and cannot change authoritative process/job state.
- [ ] CLI, HTTP, Tauri, and desktop expose equivalent production behavior and render every process/job/run state, including `timed_out`.
- [ ] The installed user LaunchAgent, desktop client mode, backup, upgrade, rollback, and uninstall preserve one owner and user data.
- [ ] `cargo check --workspace`, `cargo test --workspace`, `pnpm --dir crates/desktop/ui typecheck`, and `pnpm --dir crates/desktop/ui build` exit `0` on completed work.
- [ ] Interactive macOS LaunchAgent, login/reboot, process rollout, scheduler downtime/DST, log rollover, alert, CLI, desktop, backup, upgrade, rollback, and uninstall scenarios all have recorded observed `pass` results; any `fail`, ignored, or unrun result blocks production-ready status.
- [ ] Existing single-instance and UTC-cron definitions remain behavior-compatible after migration.
- [ ] Release configuration contains no credentials and no artifact is published, signed, notarized, or deployed without separate approval.
